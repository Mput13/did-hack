# F2. Бонусный трек: SLAM вместо готовой карты

## Вопрос

Условие хакатона: «SLAM вместо готовой карты: построить карту самостоятельно через SLAM Toolbox (начало координат
карты должно совпасть с мировым)». Ключ `pixi run demo --slam` существовал, но не проверялся, а робот при нём
всё равно ехал по готовой карте из `turtlebot3_navigation2`. Может ли робот в нашем стенде (Gazebo Sim Harmonic,
ROS 2 Jazzy) построить карту через SLAM Toolbox в мировых координатах и ездить по ней, не получая готовой карты?

## Гипотеза и что её опровергнет

Гипотеза: SLAM Toolbox по `/scan` и одометрии строит карту арены, начало координат которой совпадает с мировым,
и этой карты хватает для планирования пути, езды к точке и автономной миссии.

Опровергает (порог взят из обзора `research/notes/K4.md` до измерений): хотя бы один из девяти столбов мира
найден на карте дальше 10 см от своего места, либо найдены не все девять, либо с готовой картой совпало меньше
90 % увиденных клеток, либо робот при езде по этой карте сталкивается.

## Что сделано

Работа в Gazebo (без окна, своя сеть `ROS_DOMAIN_ID=35`, `GZ_PARTITION=did_f2`), по одному экземпляру за раз.
Три полных прогона 8.10: объезд → сверка → точка назначения → автономная миссия.

1. **SLAM Toolbox в стенде заработал без правок кода узла.** Мешали две вещи в нашей обвязке:
   - `env/slam_demo.yaml`: кадр одометрии был `odom`, и SLAM публиковал `slam_map → odom`, хотя у `odom` уже
     есть родитель `map` (его публикует стенд). У кадра оказывалось два родителя.
   - `did/pilot.py`: сетка SLAM при показе сдвигалась на точку старта в коде пульта — пересчёт жил отдельно от
     карты и ни разу не сверялся с миром.
2. **Начало координат.** Выбран способ «дать SLAM одометрию сразу в мировом кадре»: `odom_frame: map`. Кадр `map`
   стенд публикует как постоянное преобразование «одометрия + старт (−2,0; −0,5)» — ровно формула из условия
   («поза в мире = старт + одометрия»). SLAM Toolbox ставит первую позу графа туда, где робот стоит в этом кадре,
   то есть в (−2,0; −0,5), и вся карта — тема `/slam/map`, поле `origin`, сохранённый файл — сразу в мировых
   координатах. Дерево кадров: `slam_map → map → odom → base_footprint → base_scan`, у каждого один родитель.
   Почему не другие способы: параметр `map_start_pose` у slam_toolbox действует только вместе с загрузкой
   сохранённой карты (это по исходному коду узла, отдельно в стенде не проверял); отдельный постоянный кадр
   `world → slam_map` исправил бы только дерево кадров, а сама сетка осталась бы со сдвигом, и каждый потребитель
   должен был бы помнить о пересчёте; пересчёт при приёме — то же самое, но в нашем коде. Выбранный способ не
   требует пересчёта нигде, а проверяется числом (п. 3).
   Кадр карты называется `slam_map`, а не `map`: имя `map` и тема `/map` в стенде заняты готовой картой судьи.
3. **Измерение — `tools/slam_check.py`** (функции в `did/slam_map.py`): доля увиденного пола; доля увиденных
   клеток, совпавших с готовой картой; центр каждого из девяти столбов (подгонка окружности радиуса 0,15 м по
   занятым клеткам) и его ошибка; сдвиг и поворот начала координат по столбам. Той же меркой измерена сама
   готовая карта. Сетки и числа трёх прогонов лежат в `research/findings/F2/`.
4. **Режим без готовой карты — `pixi run demo --slam-map`** (`tools/demo.py`, `did/pilot.py`, `did/slam_map.py`):
   - `SlamArena` — арена для навигации из сетки SLAM: свободен только увиденный пол, связанный с роботом, всё
     неувиденное считается преградой; щели в одну-две клетки между соседними лучами лидара считаются полом;
   - граф путей пульта перестраивается на каждой новой сетке (раз в секунду, 1–2 мс);
   - поза — одометрия, исправленная преобразованием `slam_map → map` из `/tf` (`SlamPose`), наша поправка по
     лидару и готовой карте (`did/localize.py`) в этом режиме не создаётся;
   - новая команда пульта `explore` и кнопка «Построить карту»: робот едет к ближайшей по пути границе
     увиденного, пока границы не кончатся; точка в неувиденном месте отклоняется;
   - автономная миссия: агент получает снимок `SlamArena` на момент старта и `SlamPose` вместо своей поправки.
   - страница (`lab/views/pilot.js`, `lab/pilot.css`): в этом режиме показывается карта SLAM, галочка «Эталонная
     карта» снята, подпись «карта SLAM, готовой нет», плитка «Откуда поза: колёса + SLAM».
5. Проверки `tests/test_slam_map.py` (9 штук): перенос сетки, арена, границы, сверка (в том числе: карта, сдвинутая
   на 20 и 10 см, обнаруживается), пульт на быстром симуляторе в режиме карты SLAM, неизменность обычного режима.
6. `docs/demo_script.md`: раздел «Бонусный трек: SLAM вместо готовой карты» и команды.

**Что от готовой карты осталось в режиме `--slam-map`** (проверено по коду: `load_arena` и `Pilot.arena`):
- две плитки на странице — «Карта построена» и «Совпадение с эталоном» (`RosWorld.slam_view`, `compare`) и
  такие же числа у нашей собственной карты по лидару (`OccupancyMapper`), которая в этом режиме только рисуется
  вторым слоем; на решения робота не влияют;
- рамка рисунка карты на странице и серая подложка (подложка по умолчанию выключена);
- судья: столкновения, образцы, счёт — по своей карте; он не агент;
- `RosWorld.scenario = generate(level, seed, load_arena())` — только подпись записи миссии, если судья не
  прислал сценарий;
- решётка 120×120 клеток по 5 см на квадрате ±3 м (`CROP` из `did/arena.py`) — размер рабочей области, не карта.
В планирование пути, проверку точек, выбор границ, позу и в агента миссии готовая карта не попадает.
Известная точка старта (−2,0; −0,5) используется — она дана условием.

## Результат

Все числа — из `research/findings/F2/*_check.json` (их печатает `tools/slam_check.py`) и из состояния пульта.
Доля опоздавших тактов в записях миссий — 0 % во всех трёх (`lagged` из `tools/gazebo_batch.py`); наибольший
промежуток между тактами управления 0,10–0,14 с при норме 0,10.

|---|---|---|---|---|---|---|

После вычитания найденного сдвига и поворота столбы расходятся в среднем на 0,6 / 0,9 / 0,3 см: карта не

вектор старта (2,0; 0,5) из условия.

цель 5 см, домой, 0 столкновений; карта SLAM рядом — 99,9 % пола, совпадение 98,3 %.

## Коротко

SLAM — это когда робот одновременно строит карту и понимает, где он на ней находится: прикладывает каждый новый
круг лидара к уже нарисованному и так исправляет и карту, и своё положение. SLAM Toolbox — готовая программа
для этого из набора ROS. В условии хакатона это дополнительное задание: не брать карту арены готовой, а
построить её самому, причём так, чтобы координаты на ней совпадали с координатами мира.

Теперь по команде `pixi run demo --slam-map` робот готовой карты не получает вовсе. По кнопке «Построить карту»
он сам объезжает арену за минуту: едет туда, где карта ещё обрывается, пока обрывов не останется. После этого
оператор ставит точку — робот строит путь по своей карте и приезжает с точностью 4–5 см; автономная миссия
сбора образцов тоже идёт по этой карте (в трёх прогонах — без столкновений, с возвратом на базу).

Карта получается правильной: все девять столбов арены стоят на ней там же, где в мире, с ошибкой от 1,5 до
4,4 см в среднем (худший столб в худшем прогоне — 6,2 см), а с готовой картой совпадает 96–99 % клеток. Сама
готовая карта той же меркой отстоит от мира на 3,4 см — то есть карта робота не хуже той, что нам выдали.

## Вывод

Гипотеза подтверждается на трёх прогонах: 9 столбов из 9, наибольшая ошибка 6,2 см при пороге 10 см, совпадение
с готовой картой 96,0–98,7 % при пороге 90 %, столкновений нет. Трек выполнен: карта строится SLAM Toolbox,
её начало координат совпадает с мировым с точностью 1,5–4,3 см, робот планирует и едет только по ней.

## Ограничения

- Прогонов три, сценариев два, агент миссии один («С адаптацией»); «Исследователь» и «Фиксированный план» на
  карте SLAM в Gazebo не запускались. Сравнения счёта миссии с ездой по готовой карте на тех же сценариях нет —
  утверждать «не хуже» нельзя.
- Разброс сдвига от прогона к прогону не объяснён: в run1 карта ушла на 4,2 см по y и на 0,36°, в двух других —
  меньше 2 см. Предположение (не проверено): SLAM Toolbox запускается вместе со стендом и первый скан берёт,
  пока робот ещё оседает на колёса; первая поза графа задаёт всю карту. Проверка — запускать SLAM после
  оседания и сравнить несколько прогонов.
- Сдвиг по x около +1,5 см есть во всех трёх прогонах — постоянная составляющая; её источник не выяснялся.
- Агент в миссии едет по снимку карты на момент старта миссии. Если миссию запустить без объезда, он будет
  искать образцы только в увиденной с базы части арены; пульт этого не запрещает.
- Неувиденное считается преградой, щели до двух клеток между лучами — полом: преграду тоньше шага лучей на
  дальности 3 м робот в такой щели не увидит, пока не подъедет.
- Объезд выбирает границы жадно, по ближайшей; до двух мелких границ могут остаться недостроенными (run2: 2),
  на долю увиденного пола это не повлияло.
- Всё проверено без окна Gazebo (`--no-gui`); страница смотрелась во встроенном браузере в ходе одного объезда.
  С окном и записью экрана нагрузка выше — перед показом прогнать `tools/slam_check.py --explore` ещё раз.
- В быстром симуляторе режима нет (`--fast --slam-map` отклоняется): SLAM Toolbox там не запускается. Проверка
  пульта в `tests/test_slam_map.py` подставляет вместо SLAM собственную карту пульта по лидару — она проверяет
  логику объезда и планирования, а не SLAM Toolbox.
- `tools/demo_check.py` режим `--slam-map` не знает: его шаг «объезд по шести точкам» отклоняется, пока карта
  не построена. Для этого режима репетиция — `tools/slam_check.py --explore --goal 1.5 1.2`.
- Кнопка «Сбросить» карту SLAM Toolbox не стирает (только след и прогон судьи); новая карта — перезапуск показа.

## Как повторить

```bash
# терминал 1: показ без готовой карты (без окна; с окном — убрать --no-gui)
ROS_DOMAIN_ID=35 GZ_PARTITION=did_f2 ./px python tools/demo.py --no-gui --slam-map --port 8793
# терминал 2, когда пульт напишет «робот готов»: объезд, точка, сверка
ROS_DOMAIN_ID=35 ./px python tools/slam_check.py --explore --goal 1.5 1.2 --port 8793 --tag run1
# миссия — кнопкой на странице http://127.0.0.1:8793/#/pilot или командой
curl -s -X POST -H 'Content-Type: application/json' -d '{"cmd":"mission","agent":"adaptive"}' \
     http://127.0.0.1:8793/api/pilot/command

# пересчитать числа отчёта по сохранённым сеткам, без Gazebo
./px python tools/slam_check.py --from research/findings/F2/try1_map.npz
./px python tools/slam_check.py --from research/findings/F2/run1_map.npz
./px python tools/slam_check.py --from research/findings/F2/run2_map.npz

# проверки
./px python -m pytest tests/test_slam_map.py -q
./px python -m pytest tests -q
```

На показе: `pixi run demo --slam-map --open`, затем `pixi run python tools/slam_check.py` в соседнем терминале.
