# F2. Бонусный трек: SLAM вместо готовой карты

## Вопрос

Условие хакатона: «SLAM вместо готовой карты: построить карту самостоятельно через SLAM Toolbox (начало координат
карты должно совпасть с мировым)». Ключ `pixi run demo --slam` существовал, но не проверялся, а робот при нём
всё равно ехал по готовой карте из `turtlebot3_navigation2`. Может ли робот в нашем стенде (Gazebo Sim Harmonic,
ROS 2 Jazzy) построить карту через SLAM Toolbox в мировых координатах и ездить по ней, не получая готовой карты?

## Гипотеза и что её опровергнет

Гипотеза: SLAM Toolbox по `/scan` и одометрии строит карту арены, начало координат которой совпадает с мировым,
и этой карты хватает для планирования пути, езды к точке и автономной миссии.

Опровергает (порог взят из обзора `research/notes/K4.md` до измерений): хотя бы один из девяти столбов мира
найден на карте дальше 10 см от своего места, либо найдены не все девять, либо с готовой картой совпало меньше
90 % увиденных клеток, либо робот при езде по этой карте сталкивается.

## Что сделано

Работа в Gazebo (без окна, своя сеть `ROS_DOMAIN_ID=35`, `GZ_PARTITION=did_f2`), по одному экземпляру за раз.
Три полных прогона 8.10: объезд → сверка → точка назначения → автономная миссия.

1. **SLAM Toolbox в стенде заработал без правок кода узла.** Мешали две вещи в нашей обвязке:
   - `env/slam_demo.yaml`: кадр одометрии был `odom`, и SLAM публиковал `slam_map → odom`, хотя у `odom` уже
     есть родитель `map` (его публикует стенд). У кадра оказывалось два родителя.
   - `did/pilot.py`: сетка SLAM при показе сдвигалась на точку старта в коде пульта — пересчёт жил отдельно от
     карты и ни разу не сверялся с миром.
2. **Начало координат.** Выбран способ «дать SLAM одометрию сразу в мировом кадре»: `odom_frame: map`. Кадр `map`
   стенд публикует как постоянное преобразование «одометрия + старт (−2,0; −0,5)» — ровно формула из условия
   («поза в мире = старт + одометрия»). SLAM Toolbox ставит первую позу графа туда, где робот стоит в этом кадре,
   то есть в (−2,0; −0,5), и вся карта — тема `/slam/map`, поле `origin`, сохранённый файл — сразу в мировых
   координатах. Дерево кадров: `slam_map → map → odom → base_footprint → base_scan`, у каждого один родитель.
   Почему не другие способы: параметр `map_start_pose` у slam_toolbox действует только вместе с загрузкой
   сохранённой карты (это по исходному коду узла, отдельно в стенде не проверял); отдельный постоянный кадр
   `world → slam_map` исправил бы только дерево кадров, а сама сетка осталась бы со сдвигом, и каждый потребитель
   должен был бы помнить о пересчёте; пересчёт при приёме — то же самое, но в нашем коде. Выбранный способ не
   требует пересчёта нигде, а проверяется числом (п. 3).
   Кадр карты называется `slam_map`, а не `map`: имя `map` и тема `/map` в стенде заняты готовой картой судьи.
3. **Измерение — `tools/slam_check.py`** (функции в `did/slam_map.py`): доля увиденного пола; доля увиденных
   клеток, совпавших с готовой картой; центр каждого из девяти столбов (подгонка окружности радиуса 0,15 м по
   занятым клеткам) и его ошибка; сдвиг и поворот начала координат по столбам. Той же меркой измерена сама
   готовая карта. Сетки и числа трёх прогонов лежат в `research/findings/F2/`.
4. **Режим без готовой карты — `pixi run demo --slam-map`** (`tools/demo.py`, `did/pilot.py`, `did/slam_map.py`):
   - `SlamArena` — арена для навигации из сетки SLAM: свободен только увиденный пол, связанный с роботом, всё
     неувиденное считается преградой; щели в одну-две клетки между соседними лучами лидара считаются полом;
   - граф путей пульта перестраивается на каждой новой сетке (раз в секунду, 1–2 мс);
   - поза — одометрия, исправленная преобразованием `slam_map → map` из `/tf` (`SlamPose`), наша поправка по
     лидару и готовой карте (`did/localize.py`) в этом режиме не создаётся;
   - новая команда пульта `explore` и кнопка «Построить карту»: робот едет к ближайшей по пути границе
     увиденного, пока границы не кончатся; точка в неувиденном месте отклоняется;
   - автономная миссия: агент получает снимок `SlamArena` на момент старта и `SlamPose` вместо своей поправки.
   - страница (`lab/views/pilot.js`, `lab/pilot.css`): в этом режиме показывается карта SLAM, галочка «Эталонная
     карта» снята, подпись «карта SLAM, готовой нет», плитка «Откуда поза: колёса + SLAM».
5. Проверки `tests/test_slam_map.py` (после второго круга — 28): перенос сетки, арена, границы, сверка (в том
   числе: карта, сдвинутая на 20 и 10 см, обнаруживается), пульт на быстром симуляторе в режиме карты SLAM,
   неизменность обычного режима; проверки второго круга перечислены в разделе «Исправления по ревью».
6. `docs/demo_script.md`: раздел «Бонусный трек: SLAM вместо готовой карты» и команды.

**Что от готовой карты осталось в режиме `--slam-map`** (проверено по коду: `load_arena` и `Pilot.arena`):
- две плитки на странице — «Карта построена» и «Совпадение с эталоном» (`RosWorld.slam_view`, `compare`) и
  такие же числа у нашей собственной карты по лидару (`OccupancyMapper`), которая в этом режиме только рисуется
  вторым слоем; на решения робота не влияют;
- рамка рисунка карты на странице и серая подложка (подложка по умолчанию выключена);
- судья: столкновения, образцы, счёт — по своей карте; он не агент;
- `RosWorld.scenario = generate(level, seed, load_arena())` — только подпись записи миссии, если судья не
  прислал сценарий;
- решётка 120×120 клеток по 5 см на квадрате ±3 м (`CROP` из `did/arena.py`) — размер рабочей области, не карта.
В планирование пути, проверку точек, выбор границ, позу и в агента миссии готовая карта не попадает.
Известная точка старта (−2,0; −0,5) используется — она дана условием.

## Исправления по ревью

Вердикт ревью первого круга — «можно после исправлений»: четыре блокирующие находки и две в ограничения.
Каждое воспроизведение ревьюера стало проверкой в `tests/test_slam_map.py`. На прежнем коде из 19 новых
проверок падают 17 (часть — уже на новом виде ответа `slam_tf`, словаре с возрастом данных; по существу
четыре блокирующих случая на прежнем коде воспроизводил сам ревьюер); проходят две — миссия до конца и
сравнение обычного режима с main, как и должно быть.

**1. Цель стала преградой — робот ехал к ней и зависал (блокирует). Исправлено.**
Было: после смены карты `_drive` перепланировал путь до ближайшего разрешённого узла и снова дописывал в конец
исходную цель; лидар у преграды обнулял скорость, сторож застревания (он считает время команды «вперёд») молчал.
Сделано (`did/pilot.py`, только при `slam_nav`):
- перед каждым построением пути цель проверяется на нынешней карте (`_target_ok`): занятая или вне увиденного
  пола — маршрут останавливается, робот стоит, оператор видит «Точка N на новой карте SLAM оказалась в преграде
  или вне увиденного пола: маршрут остановлен. Поставьте точку заново»; цель, оказавшаяся чуть ближе 17 см к
  стене (карта уточнилась на клетку), передвигается на ближайшее разрешённое место не дальше 15 см, как при
  постановке точки; в объезде такая граница бросается;
- построенный путь вместе с последним отрезком до цели проверяется той же функцией, что и при смене карты;
- два срока (`_overdue`): робот не сдвинулся на 5 см за 10 с — езда прекращается («Езда остановлена: робот 10 с
  не продвигается…»); весь подъезд дольше 30 с + 15 с на метр пути — тоже. В объезде граница бросается и робот
  едет к следующей, так что объезд ограничен: не больше 40 подъездов, каждый со сроком.
Закреплено: `test_target_that_became_an_obstacle_stops_the_route` (воспроизведение ревьюера: остановка не
позже 5 тактов вместо 80 с стояния), `test_target_slightly_too_close_to_a_wall_is_moved_not_dropped`,
`test_obstacle_missing_from_the_map_ends_the_drive_by_deadline` (столба нет на карте, в мире есть: остановка
через 13,7 с с сообщением, без столкновения), `test_every_leg_and_the_whole_exploration_are_bounded_in_time`.

**2. Непригодная новая карта оставляла в силе старую (блокирует). Исправлено.**
Было: версия обновлялась до проверки; если на сетке негде встать, прежние арена, граф и путь оставались, а
странице сообщалось `ready=True` с новой версией.
Сделано (`_refresh_nav`): версия, арена, граф и то, что видит оператор, меняются вместе. На непригодной сетке
графа нет, путь стёрт, езда остановлена с сообщением «Новая карта от SLAM Toolbox непригодна для езды…»,
`nav.ready=False`, площадь пола — по новой сетке; команды «Ехать», «Домой», «Построить карту», «Миссия» и
постановка точек отклоняются. Выбор: движение само не возобновляется — когда приходит пригодная карта,
оператор видит «Карта от SLAM Toolbox снова пригодна для езды» и нажимает «Ехать» (маршрут сохранён; прерванный
объезд запускается кнопкой заново, карта при этом не теряется). Так же устроены остановки по п. 1 и 3: одно
правило — «робот встал по причине карты или SLAM → причина на экране → оператор нажимает снова».
Закреплено: `test_unusable_new_map_takes_the_old_one_out_of_service` (воспроизведение ревьюера и то же на ходу).

**3. SlamPose молча отключал защиту и не замечал молчания SLAM (блокирует). Исправлено.**
Было: признаки `lost`, `unsure`, `slip`, `relocations` — константы; возраст `/tf` и сетки не велся.
Сделано:
- `RosWorld.slam_tf` отдаёт преобразование вместе с возрастом последнего сообщения `/tf` и последней сетки
  (по часам симуляции, время получения); `/tf` принимается только с обоими именами кадров (`slam_map` → `map`),
  сетка — только в кадре `slam_map` и целая;
- `SlamPose` (`did/slam_map.py`) считает признаки по этим данным: `lost` — преобразования нет, оно старше
  1,0 с или сетка старше 5,0 с; `relocations` — поправка сдвинула позу больше чем на 10 см или 0,15 рад за
  такт (и 2 с после этого держится `unsure`); `slip` — сдвиг позы поправкой за пять сканов, как в
  `did/localize.py`. Устаревшее преобразование не применяется; последняя принятая поправка остаётся;
- сроки: `/tf` публикуется 50 раз в секунду (`transform_publish_period: 0.02`), 1,0 с — это 50 пропусков, робот
  за это время проезжает не больше 24 см; сетка публикуется раз в секунду (`map_update_interval: 1.0`), 5,0 с —
  пять пропусков подряд. В Gazebo измерено: возраст `/tf` 0,01–0,02 с, сетки — до 0,97 с, в том числе у
  стоящего робота (сетка публикуется и когда ничего не меняется);
- ручная езда (`_watch_slam`): при `lost` робот останавливается с сообщением, команды отклоняются с той же
  причиной; при восстановлении путь сбрасывается, оператор видит «SLAM Toolbox снова на связи»; при скачке
  путь сбрасывается и робот стоит, пока держится `unsure`;
- миссия: останавливает та же защита агента, что при потере положения по лидару (`did/agent.py::_guard`, файл не
  менялся): по `lost` агент стоит и сам сообщает сторожам простоя, что это ожидание (`_waiting`, `_stuck`), по
  `relocations` строит путь заново, по `slip` отъезжает; пульт показывает причину на странице. Если SLAM не
  вернулся за 20 с, агент, как и в обычном режиме, едет на базу медленно и по лидару — миссия не висит.
  Агент без защиты (`guard` или `localize` выключены) в режиме карты SLAM не запускается — одна явная ветка в
  `_cmd_mission`; у всех трёх агентов пульта защита включена.
Закреплено: `test_slam_pose_reports_silence_instead_of_constant_ok` (воспроизведение ревьюера, возраст `/tf` и
сетки, часы пошли заново), `test_slam_pose_sees_jumps_and_slip`, `test_silent_slam_stops_manual_driving_and_says_why`,
`test_slam_jump_drops_the_path_and_pauses`, `test_silent_slam_holds_the_mission_without_a_false_escape`
(15 с молчания: агент стоит, ложного отъезда нет, миссия доходит до конца),
`test_slam_that_never_returns_does_not_hang_the_mission`; на живом стенде — таблица заморозки в «Результате».

**4. «Найдено 9 столбов» допускало ложное подтверждение (блокирует). Исправлено.**
Было: столбом считались любые шесть занятых клеток в окне; девять квадратов 15×15 см давали «9 из 9».
Сделано (`pillars`): столб засчитывается, только если клетки лежат кольцом радиуса столба — средний квадрат
отклонения от окружности не больше 3,5 см (полудиагональ клетки), ни одна клетка не дальше 8,5 см, занято не
меньше 9 секторов из 12 (отрезок стены не даёт больше половины круга). Проверяется кольцо целиком вокруг
найденного центра, а не только клетки в окне. Неподтверждённый объект столбом не считается, в выводе
`slam_check.py` у него причина; итог приёмки — функция `accepted`. Пороги взяты из размера клетки, но выбраны,
когда значения у настоящих столбов уже были известны (остаток 2,0–2,9 см, 10–12 секторов), — запас по остатку
небольшой.
Три сохранённые сетки пересчитаны: число подтверждённых столбов не изменилось — 9 из 9 в каждой, ошибки и
совпадение те же до десятой доли сантиметра и процента.
Закреплено: `test_only_a_ring_of_pillar_radius_counts_as_a_pillar` (квадрат, отрезок, сплошное пятно: 0 из 9),
`test_random_cells_are_not_pillars` (100 карт со случайными клетками: кольцом случайно вышло 1 место из 900, ни
одна карта приёмку не проходит), `test_a_half_seen_pillar_is_not_confirmed_and_real_maps_still_pass`.

**5. Путь сохранялся при запасе 0,10 м, а граф строится с 0,17 м (в ограничения). Исправлено.**
Порог один — `INFLATE`; проверяются и точки оставшегося пути, и отрезки между ними с шагом в полклетки
(`_path_ok`). Закреплено: `test_path_is_dropped_by_the_same_margin_the_graph_is_built_with`.

**6. «Карта робота не хуже выданной» сильнее данных (в ограничения). Исправлено.**
Формулировка в «Коротко», в «Выводе» и в `docs/demo_script.md` заменена: карта удовлетворила выбранным порогам;
совпадение начала координат называется вместе со сдвигом и поворотом; в двух прогонах из четырёх карта SLAM
стоит в мире хуже готовой.

**Замечания о проверках.** Добавлены: проверки на п. 1–5; миссия в режиме карты SLAM на быстром симуляторе до
конца (`test_mission_on_the_slam_map_runs_to_the_end`: возврат на базу, без столкновений, защита зря не
срабатывала); сравнение обычного режима с main (`test_normal_mode_matches_main`, эталон
`tests/data/pilot_main_poses.json` снят с кода main, коммит 165c123, сценарием `tests/data/pilot_main_poses.py`).

**Второй круг ревью.** Вердикт — «можно после исправлений», одна блокирующая находка: находка 2 была закрыта
только для ручной езды. В миссии агент едет по снимку карты, свежие сетки пульт не смотрел, и непригодная новая
карта ничего не меняла: за 50 тактов робот проезжал ещё 0,72 м при зелёном состоянии на экране. Исправлено ведущим
(`did/pilot.py::_check_grid`, `_slam_reading`; `did/slam_map.py::SlamPose`): в миссии каждая новая сетка
проверяется до команды агента; если на ней роботу негде стоять, `SlamPose` сообщает о потере положения с причиной
«карта непригодна», и дальше работает та же защита агента, что при молчании SLAM, — агент прекращает езду по
маршруту и ждёт (после первых 5 с защита допускает короткие переползания по лидару, до 0,08 м/с: в проверке ревьюера
за 20 с набралось 0,29 м), вернулась пригодная карта — едет дальше, не вернулась за 20 с после начала ожидания —
возвращается на базу медленно, по лидару. Если в этот момент агент ждал ответа планировщика, 20 с отсчитываются
после этого ожидания; робот при этом тоже стоит. Узкое ревью правки (третий круг): замечаний, требующих правки
до показа, нет; за 50 тактов робот проходит 1 см вместо 0,72 м. На экране
`ready=False` и причина. Проверки: `test_unusable_map_during_a_mission_stops_the_agent`,
`test_map_that_stays_unusable_does_not_hang_the_mission` (до правки обе падают). Остальные пять находок первого
круга ревьюер подтвердил закрытыми, обычный режим — совпадающим с main на всех 116 записях эталона. В Gazebo
этот случай не воспроизводился: непригодной сетки SLAM Toolbox в прогонах не присылал.

## Коротко

SLAM — это когда робот одновременно строит карту и понимает, где он на ней находится: прикладывает каждый новый
круг лидара к уже нарисованному и так исправляет и карту, и своё положение. SLAM Toolbox — готовая программа
для этого из набора ROS. В условии хакатона это дополнительное задание: не брать карту арены готовой, а
построить её самому, причём так, чтобы координаты на ней совпадали с координатами мира.

Теперь по команде `pixi run demo --slam-map` робот готовой карты не получает вовсе. По кнопке «Построить карту»
он сам объезжает арену за минуту: едет туда, где карта ещё обрывается, пока обрывов не останется. После этого
оператор ставит точку — робот строит путь по своей карте и приезжает с точностью 4–5 см по своей же оценке
положения; автономная миссия сбора образцов тоже идёт по этой карте (в пяти прогонах — без столкновений, с
возвратом на базу).

В пяти сохранённых прогонах карта удовлетворила выбранным порогам: все девять столбов арены подтверждены
(кольцо нужного радиуса) и стоят не дальше 10 см от своих мест — в среднем от 1,5 до 5,7 см, худший столб
9,5 см (пятый прогон; запас до порога — полсантиметра); с готовой картой совпадает 95,8–98,7 % клеток при пороге
90 %. Начало координат карты совпадает с мировым со сдвигом 1,5–5,2 см и поворотом до 1,29°. Готовая карта той же меркой отстоит от мира на 3,4 см: в
двух прогонах карта робота точнее её, в двух — грубее.

После ревью режим перестал зависать и ездить по устаревшему. Если SLAM Toolbox замолчал, робот через секунду
останавливается и пишет причину на экране; в миссии он прекращает езду по маршруту, ждёт (изредка переползая
на несколько сантиметров по лидару) и, не дождавшись за 20 с, возвращается на базу.
Если на новой карте цель оказалась в преграде, или новая карта непригодна, или робот 10 с не продвигается —
езда прекращается с понятным сообщением, а не стоит молча. Это проверено и на живом стенде: узел SLAM
замораживали на 8 с во время езды и во время миссии.

## Вывод

Гипотеза подтверждается на пяти прогонах, в пятом — на пределе: подтверждено 9 столбов из 9, наибольшая ошибка 9,5 см при пороге
10 см, совпадение с готовой картой 95,8–98,7 % при пороге 90 %, столкновений нет. Трек выполнен: карта
строится SLAM Toolbox, её начало координат совпадает с мировым со сдвигом 1,5–5,2 см и поворотом до 1,29°,
робот планирует и едет только по ней. Четыре блокирующие находки ревью исправлены и закреплены проверками.

## Ограничения

- «Непригодная карта» в миссии — это сетка, на которой роботу негде стоять. Карта, которая осталась пригодной,
  но изменилась под уже построенным путём агента, в миссии не перепроверяется: агент едет по снимку, от столкновения
  его защищает лидар. Лишнее кольцо вдали от девяти известных мест столбов проверка столбов не замечает: она
  подтверждает столбы там, где они должны быть, а не отсутствие других круглых предметов.
- Прогонов четыре, сценариев два, агент миссии один («С адаптацией»); «Исследователь» и «Фиксированный план» на
  карте SLAM в Gazebo не запускались. Сравнения счёта миссии с ездой по готовой карте на тех же сценариях нет —
  утверждать «не хуже» нельзя.
- Пятый прогон (main после вливания работ M1 и страницы показа; объезд 67 с, 14 подъездов, точка — 4 см, миссия
  «Исследователь» на карте SLAM: 5 из 5, возврат, счёт 72,1, столкновений нет) дал худшее совмещение из пяти: поворот
  карты +1,29°, худший столб 9,5 см при пороге 10 см. Порог не превышен, но на живом показе сверка может его
  превысить; сетка и числа — `research/findings/F2/main5_*`. Говорить жюри: «совпадает с точностью около 5 см», а не
  «совпадает».
- Разброс сдвига от прогона к прогону не объяснён: в run1 и r2a карта ушла на 4,2 и 5,0 см по y (поворот −0,36°
  и +0,25°), в двух других — меньше 2 см. Запас до порога 10 см у худшего столба — 3,8 см. Предположение (не проверено): SLAM Toolbox запускается вместе со стендом и первый скан берёт,
  пока робот ещё оседает на колёса; первая поза графа задаёт всю карту. Проверка — запускать SLAM после
  оседания и сравнить несколько прогонов.
- Сдвиг по x около +1,5 см есть во всех трёх прогонах — постоянная составляющая; её источник не выяснялся.
- Агент в миссии едет по снимку карты на момент старта миссии. Если миссию запустить без объезда, он будет
  искать образцы только в увиденной с базы части арены; пульт этого не запрещает.
- Неувиденное считается преградой, щели до двух клеток между лучами — полом: преграду тоньше шага лучей на
  дальности 3 м робот в такой щели не увидит, пока не подъедет.
- Объезд выбирает границы жадно, по ближайшей; до двух мелких границ могут остаться недостроенными (run2: 2),
  на долю увиденного пола это не повлияло.
- Всё проверено без окна Gazebo (`--no-gui`); страница смотрелась во встроенном браузере в ходе одного объезда.
  С окном и записью экрана нагрузка выше — перед показом прогнать `tools/slam_check.py --explore` ещё раз.
- В быстром симуляторе режима нет (`--fast --slam-map` отклоняется): SLAM Toolbox там не запускается. Проверка
  пульта в `tests/test_slam_map.py` подставляет вместо SLAM собственную карту пульта по лидару — она проверяет
  логику объезда и планирования, а не SLAM Toolbox.
- `tools/demo_check.py` режим `--slam-map` не знает: его шаг «объезд по шести точкам» отклоняется, пока карта
  не построена. Для этого режима репетиция — `tools/slam_check.py --explore --goal 1.5 1.2`.
- Кнопка «Сбросить» карту SLAM Toolbox не стирает (только след и прогон судьи); новая карта — перезапуск показа.

Ограничения исправлений второго круга:
- После правок сделан один запуск Gazebo (r2a: объезд, точка, миссия, две заморозки SLAM), второй не делался:
  машина занята чужими расчётами (загрузка за минуту 7,9 перед запуском, до 11,4 во время него вместе с
  нашим Gazebo; опоздавших тактов 0 %). Трудный уровень и агенты «Исследователь» и «Фиксированный план» после
  правок в Gazebo не прогонялись.
- Молчание SLAM проверено заморозкой узла. Скачок поправки и проскальзывание проверены только на подставных
  преобразованиях в быстром симуляторе: в Gazebo их не случилось (скачков 0), пороги 10 см и 0,15 рад выбраны
  рассуждением, а не измерением. Порог проскальзывания 4 см за секунду — из защиты агента (`did/agent.py`): если
  SLAM Toolbox при замыкании цикла сдвинет позу против хода на 4 см и больше, агент остановится и отъедет зря.
  В двух миссиях после правок такого не было.
- Неверная локализация при живом SLAM, которая уводит позу плавно (меньше 10 см за такт), не обнаруживается.
- Возраст данных считается по времени получения и по часам симуляции. Если встанет сам Gazebo, это видно по
  другому признаку — «Нет связи со стендом».
- После остановки по причине карты или SLAM робот сам не трогается: оператор нажимает «Ехать» заново;
  прерванный объезд начинается кнопкой заново (уже построенная карта сохраняется).
- В миссии, если SLAM молчит дольше 20 с, агент едет на базу по одометрии с последней поправкой — так же, как
  в обычном режиме при потере положения. Пока ждёт, раз в несколько секунд переползает на 8 см/с туда, где по
  лидару свободно (это поведение защиты агента, не менялось).
- Агент в миссии по-прежнему едет по снимку карты на момент старта; непригодная или изменившаяся сетка во
  время миссии на него не влияет.
- Сроки «10 с без продвижения» и «30 с + 15 с на метр» действуют только в режиме карты SLAM; обычный режим не
  менялся. Если управление долго идёт замедленно из-за перегрузки машины (8 см/с), срок подъезда может
  истечь раньше приезда — оператор увидит причину и нажмёт «Ехать» снова.
- Проверка столбов: недосмотренный столб (кольцо видно меньше чем на три четверти) не засчитывается, поэтому
  сверка до конца объезда покажет меньше девяти. Случайная россыпь клеток изредка похожа на кольцо (1 место из
  900 в проверке); девять таких совпадений разом практически исключены.
- Страница нового элемента для здоровья SLAM не получила: причина остановки видна в строке сообщения и в
  списке событий; возраст данных есть в состоянии пульта (`nav.slam`), но не рисуется.
- Сравнение обычного режима с main — один сценарий быстрого симулятора, 110 с.

## Как повторить

```bash
# терминал 1: показ без готовой карты (без окна; с окном — убрать --no-gui)
ROS_DOMAIN_ID=35 GZ_PARTITION=did_f2 ./px python tools/demo.py --no-gui --slam-map --port 8793
# терминал 2, когда пульт напишет «робот готов»: объезд, точка, сверка
ROS_DOMAIN_ID=35 ./px python tools/slam_check.py --explore --goal 1.5 1.2 --port 8793 --tag run1
# миссия — кнопкой на странице http://127.0.0.1:8793/#/pilot или командой
curl -s -X POST -H 'Content-Type: application/json' -d '{"cmd":"mission","agent":"adaptive"}' \
     http://127.0.0.1:8793/api/pilot/command

# молчание SLAM на живом стенде: заморозить узел на 8 с и отпустить
kill -STOP $(pgrep -f async_slam_toolbox_node); sleep 8; kill -CONT $(pgrep -f async_slam_toolbox_node)

# пересчитать числа отчёта по сохранённым сеткам, без Gazebo
./px python tools/slam_check.py --from research/findings/F2/try1_map.npz
./px python tools/slam_check.py --from research/findings/F2/run1_map.npz
./px python tools/slam_check.py --from research/findings/F2/run2_map.npz
./px python tools/slam_check.py --from research/findings/F2/r2a_map.npz

# проверки
./px python -m pytest tests/test_slam_map.py -q
./px python -m pytest tests -q
```

На показе: `pixi run demo --slam-map --open`, затем `pixi run python tools/slam_check.py` в соседнем терминале.
