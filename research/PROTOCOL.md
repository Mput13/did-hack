# Исследовательский контур: кто что делает

Цель — чтобы новые гипотезы проверялись без участия человека, но в основную ветку попадало только проверенное.

## Роли

| Роль | Кто | Что делает |
|---|---|---|
| Ведущий | основной ассистент в треде проекта | ведёт план (`agenda.yaml`), раздаёт работу, перепроверяет числа, вливает в `main`, обновляет `explain.html` |
| Исследователь | Gemini 3.8 Flash (Antigravity) | **работа со знаниями, не код**: ищет методы, опубликованные опыты, похожие проекты; пишет обзор со ссылками и идеями, что проверить у нас |
| Инженер | Claude Opus 5.5 | реализация: код исследования, опыт, отчёт с числами — в своей ветке |
| Ревьюер | GPT-6.1 Sol | независимое ревью кода инженера до слияния; сам код не пишет |
| Советники | Claude Fable 5.1 и GPT-6 Astra | направление исследований и спорные развилки; вызываются редко |

Порядок: обзор исследователя → гипотеза в плане → реализация инженером → ревью → правки инженера → перепроверка чисел
ведущим → слияние и запись на странице.

**Про код от Gemini.** В первый день часть исследований по ошибке ведущего была отдана Gemini целиком, с кодом (R1, R3,
R4, R8, R13). К этому коду относимся скептически: воспроизводимость чисел доказывает только повторяемость, а не
правильность. Такой код либо проходит ревью (R1, R4, R8), либо принимается инженером как черновик и доводится (R3, R13).
Впредь код Gemini не поручается.

## Правила для инженера (ветка исследования)

1. **Работать только в своём рабочем дереве** `/Users/a/MAI/DID-research/<R#>` (ветка `research/<R#>`). Основной каталог
   `/Users/a/MAI/DID` не менять вообще: там идёт подготовка к показу.
2. **Команды — через `./px`** из корня своего дерева: `./px python -m pytest tests -q`,
   `./px python -m did.experiments <опыт> --jobs 4`. Задачи `pixi run <имя>` не использовать: они исполняются в основном каталоге.
3. **Gazebo, ROS и сеть не запускать.** Только быстрый симулятор. Языковые модели — только имитатор (`mock`).
4. **Новое поведение — за флажком, по умолчанию выключено.** Существующие варианты агента и существующие опыты E1–E14
   должны давать те же числа, что и раньше.
5. **Опыт описывается файлом** `experiments/<E#>.yaml` по образцу соседних: вопрос, гипотеза, способ проверки, что её
   опровергнет. Сценарии — только отложенные (номера с 1001, это значение по умолчанию). Подбирать параметры можно
   только на сценариях 1–80.
6. **Числа — только из `runs/<E#>/summary.json`**, никаких чисел по памяти. Вывод делается по парным разностям и их
   95% интервалу: если ноль внутри интервала — «различие не показано», а не «лучше».
   Два уточнения от советников (8.10). «Ноль внутри интервала» не значит «бесполезно»: чтобы утверждать «не хуже»,
   заранее назови допуск (например, 1 очко) и проверь, что интервал целиком внутри него. И если вопрос — «помогает ли
   механизм именно при изменении среды», считай парную разность разностей: (с механизмом − без него) при изменении
   минус (с механизмом − без него) без изменения.
7. **Отрицательный результат — тоже результат.** Гипотеза не подтвердилась — так и написать, ничего не подгоняя.
8. Перед сдачей: `./px python -m pytest tests -q` проходит целиком; всё закоммичено в своей ветке
   (`git add -A && git commit`), автор — как настроено в репозитории; `git push` не делать.

## Что сдаёт инженер

Файл `research/findings/<R#>.md` в своей ветке, строго по разделам:

```
# <R#>. <название>
## Вопрос
## Гипотеза и что её опровергнет
## Что сделано            — какие файлы изменены и зачем, какой опыт добавлен, сколько прогонов
## Результат              — таблица чисел из summary.json: среднее, 95% интервал, парные разности
## Вывод                  — подтверждается / опровергается / различие не показано, одной-двумя фразами
## Ограничения            — чего этот опыт не показывает
## Как повторить          — точные команды
```

## Что сдаёт исследователь-аналитик

Обзор на 2–3 страницы в `research/notes/<K#>.md`: короткий ответ; что известно (со ссылками, которые он сам открыл);
что применимо к нашему роботу — таблицей «идея, откуда, что сделать, как проверить и что её опровергнет, трудоёмкость,
уверенность»; чего делать не стоит; список источников. Код и файлы проекта исследователь не трогает.

## Что делает ведущий с результатом

1. Отдаёт разницу с `main` ревьюеру; замечания возвращает инженеру. Прогоняет проверки в дереве исследования.
2. Сам пересчитывает опыт и сверяет числа с отчётом. Не сошлось или ревью не пройдено — исследование возвращается.
3. Вливает в `main`, пересчитывает опыт там, добавляет запись в журнал исследований страницы `explain.html`.

## Пауза

Перед показом или репетицией: `touch research/PAUSE` в основном каталоге (новые расчёты исследователей не стартуют),
`python3 tools/research.py pause` — то же и ещё остановить идущие. Снять: `python3 tools/research.py resume`.
