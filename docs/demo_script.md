# Сценарий показа: пульт робота

Показ идёт с одного Mac: слева окно Gazebo, справа браузер со страницей «Демонстрация» (адрес `…/#/pilot`).
Регламент финала — 5 минут демо и 2 минуты вопросов. Сценарий ниже занимает 4 минуты езды и оставляет минуту
на бонусы; стенд поднимается заранее, до выхода к жюри.

**Что показываем (выбрано измерением 8.10, `research/findings/F1.md`):** трудный уровень, сценарий 2, агент
«Исследователь, пережидает сбой датчика» (`scientist_v2`). Пять засчитанных прогонов Gazebo из пяти (четыре 8.10 и
репетиция на слитом коде 9.10): собрано 7 из 7, возврат, счёт 90,8–91,9, столкновений и заездов в опасные зоны нет,
миссия 133–153 с. Ещё один прогон не засчитан (машина была перегружена, 4 % опоздавших тактов): в нём тоже 7 из 7 и
счёт 91,8, но сбой датчика робот заметил только через 25 с. Запасная пара — тот же агент на сценарии 3: два прогона
8.10 (счёт 91,1 и 80,6; собрано 7 и 6 из 7; возврат, штрафов нет) и дневной прогон ведущего (счёт 80,9).

Требования жюри, которые закрывает показ:

| № | Требование | Где видно |
|---|---|---|
| 1 | Работающий прототип робота в среде | окно Gazebo: TurtleBot3 Burger на арене |
| 2 | Генерация карты или статичная карта | карта на странице проявляется по лидару; бледная подложка — эталонная карта |
| 3 | Положение робота на карте | оранжевый кружок со стрелкой, след, лучи лидара |
| 4 | Задать точку назначения или маршрут | клик по карте ставит нумерованную точку |
| 5 | Движение по заданному маршруту | кнопка «Запустить маршрут»: синий пунктир — построенный путь |
| 6 | Полный сценарий | запуск → карта → задача → движение → результат, шаги ниже |
| 7 | Среда изменилась — робот отреагировал | миссия на трудном уровне: журнал агента, раздел «Показ адаптации» ниже |

## За десять минут до показа

1. Остановить на Mac тяжёлые расчёты (серии опытов, другие Gazebo): `python3 tools/research.py pause`, после показа
   — `python3 tools/research.py resume`. Если процессор занят, команды роботу запаздывают, и робот может задеть
   столб. Проверка, что прежний показ не оставил процессов: `pgrep -fl "gz sim"` должен быть пуст.
2. В терминале, из папки проекта:

   ```bash
   pixi run demo --level hard --seed 2 --agent scientist_v2 --open
   ```

   Команда поднимает сервер интерфейса (если он ещё не запущен), стенд Gazebo с окном и пульт,
   печатает адрес страницы (`http://127.0.0.1:8765/#/pilot`) и с ключом `--open` открывает её в браузере.
   Остановить всё — `Ctrl+C` в этом терминале.
3. Расставить окна: Gazebo слева, браузер справа (страница рассчитана на ширину от 1280 точек). Во второй вкладке
   браузера открыть запись двух роботов (`…/#/run?file=M1gz/team/medium-3.json.gz`), в третьей — запасную запись
   миссии (`…/#/run?file=F1demo/scientist_v2-hard-2-main-final.json.gz`).
4. Дождаться под кнопками строки «Готов к заданию» (до неё — «Робот готовится к запуску»; 40–45 секунд от запуска).
   Агент уже выбран: команда с `--agent scientist_v2 --open` открывает страницу с этим агентом. Проверить: нажать
   задание «Собрать образцы и вернуться» — в списке «Агент» должна стоять строка **«Исследователь, пережидает сбой
   датчика»**; затем вернуться к заданию «По заданному маршруту». Если страницу открыли или обновили без
   `?agent=scientist_v2` в адресе, агента выбрать в списке вручную.
   Перед выходом нажать «Сбросить прогон»: карта и след сотрутся, судья начнёт прогон заново.
5. За полчаса до выхода — репетиция без человека (4 минуты):
   `pixi run python tools/demo_check.py --agent scientist_v2 --tour short --no-goal --expect hard 2 --min-samples 7 --clean`.
   Если показ поднялся не на 8765 (порт был занят — команда запуска пишет адрес страницы, например с `:8766`),
   добавить к репетиции тот же порт: `--port 8766`.
6. Окно браузера — не уже 1280 точек. Карта на странице закреплена, а журнал агента стоит в правой колонке ниже
   первого экрана: с первым решением миссии страница сама прокручивается так, что карта, плитки «Заряд»,
   «Пройдено», «Счёт судьи» и карточка «Последние решения агента» видны вместе. После этого страницу не прокручивать.

Gazebo): готовность через 40 с после запуска, объезд 6,9 м — 34 с, подъезд к базе перед миссией — 8 с,
миссия — 139–153 с (по часам 142–156 с). От нажатия «Запустить маршрут» до конца миссии — 3 минуты 10–25 секунд.

## Показ адаптации: что происходит в миссии и что говорить

Трудный уровень, сценарий 2. Судья трижды меняет среду и агенту об этом не сообщает: на 31-й секунде миссии
меняются грунты, на 36-й появляется новая опасная зона, на 42-й начинает шуметь датчик образцов (на 39 секунд).
Секунды ниже — время миссии (число перед каждой строкой в карточке «Последние решения агента»); в трёх репетициях
они совпали с точностью до 2–4 секунд (последний образец — до 9 секунд).

Страница «Демонстрация» показывает пять последних строк журнала, новая сверху: решения, гипотезы, их проверки и от
расследований «вопрос — опыт — вывод» (Q1, Q2…) — странность и вывод; рядом — плитки «Заряд», «Пройдено» и «Счёт
судьи». Строки «Опыт» и «Измерено» есть только в записи прогона («Посмотреть этот прогон» → «Показать
расследования»). Страница проверена 9.10 на быстром симуляторе (тот же сценарий и агент: 7 из 7, счёт 91,8); в
Gazebo с этим видом карточки показ ещё не шёл.

| Время миссии | Что на экране | Что сказать |
|---|---|---|
| 0–30 с | робот собирает три образца: на 9-й, 20-й и 30–34-й секунде; на странице «H1: образец лежит около… Проверка: подъехать вплотную и попробовать собрать» → «H1 подтверждена: образец собран» | «Каждая цель — гипотеза: „образец здесь“. Подъехал, попробовал собрать — подтвердил или опроверг» |
| 31–40 с | **в трёх засчитанных прогонах из пяти:** робот останавливается на 2–4 секунды у третьего образца (иногда поворачивается на месте); на странице «Q1. Странность: расход 5.6 ед/м при прогнозе 2.9. Возможные объяснения: …» → «Q1. Вывод: грунт здесь изменился и стал дороже, примерно ×2.1 — вероятность 99%… участок внесён в карту стоимостей» → «H4: около (0.5; 1.4) грунт дороже обычного… » → «H4 подтверждена: на 0.4 м пути расход ×2.2». Только в записи: «Опыт: постоять 2 секунды и измерить расход на месте», «Измерено: 0.01 ед/с». **В двух прогонах из пяти** строки Q1 в это время нет: робот в момент смены не был на подорожавшем участке — тогда этот абзац пропустить | «Здесь судья только что сделал грунт дороже и роботу не сказал. Робот заметил, что заряд уходит вдвое быстрее прогноза, выдвинул объяснения — течёт батарея или подорожал грунт — и поставил опыт: постоял. Заряд стоя не уходит — значит, грунт. Участок попал в карту стоимости: дальше маршруты считаются с его ценой» |
| 42–46 с | робот останавливается; на странице «Q2. Странность: показание датчика упало… / разброс показаний датчика вырос…» → «Q2. Вывод: датчик образцов стал шуметь сильнее (сбой) — вероятность 93–97%» → «Датчик образцов шумит: стою и жду, пока шум спадёт (стоять стоит 0.01 ед./с, езда по таким показаниям теряет впустую около 0.22 ед./с)» | «А теперь сломался сам датчик образцов — тоже без объявления. Робот увидел, что показания скачут, проверил стоя и сделал вывод: это сбой датчика, а не образцы» |
| 46–82 с | робот стоит 36 секунд (во всех пяти засчитанных прогонах Gazebo); строка «…стою и жду…» остаётся в карточке. Если робот тронулся раньше (в быстром симуляторе 9.10 так было один раз: «Сбой датчика закончился: шум вернулся…» через 2 с, затем новый вопрос Q3 и снова ожидание) — читать с экрана | «Он посчитал: стоять стоит сотую единицы заряда в секунду, а ездить по шумным показаниям — в двадцать раз дороже. Поэтому ждёт». **Пока он стоит — вторая вкладка: запись двух роботов, скорость 4×, 30 секунд** (бонус ниже); вернуться к 80-й секунде |
| 82 с | на странице «Ожидание датчика: 36 с, 0.36 ед. заряда. Разброс показаний стоя вернулся к 0.08»; робот поехал | «Шум спал — робот сам это заметил и поехал дальше. Ожидание стоило 0,36 единицы заряда из 60» |
| 90–141 с | ещё четыре образца (около 90-й, 104-й, 116-й и 132–141-й секунды); на 103–112-й секунде ещё один вопрос о расходе на дорогом грунте внизу справа | «Дорогие участки он находит тем же способом и вносит в карту» |
| 140–153 с | «Возвращаюсь на базу: все образцы собраны», «Финиш: возврат на базу засчитан. Собрано 7 из 7» | переход к шагу 6 |

Чего не говорить.
- Что робот «увидел новую опасную зону»: зона невидима, пока в неё не въедешь; в этом сценарии робот в неё не
  попадает, поэтому её и не находит (на странице записи так и написано: «новая опасная зона — не заметил»).
  В других сценариях реакция на зону есть (штраф → гипотеза о зоне → объезд), но это заезд со штрафом, и для
  показа мы выбрали сценарий без штрафов.
- Что на 31–40-й секунде робот «понял, что грунт изменился». Он заметил, что расход выше прогноза, и опытом
  отделил грунт от сбоя батареи. В журнале формулировка бывает и «грунт здесь изменился и стал дороже», и «здесь
  дорогой грунт»: читать с экрана то, что написано. В пяти засчитанных прогонах Gazebo тревога о расходе в первые
  секунды после смены была в трёх (через 1–2 с после въезда на участок); в двух её не было, и пометку о дорогом
  грунте агент поставил позже, на другом участке (около 72-й и 103-й секунды).
- Что робот «объезжает дорогой грунт и за счёт этого выигрывает». Участок вносится в карту стоимости, и следующие
  маршруты считаются с его ценой: где объезд дешевле — объедет, где дороже — проедет напрямик. Выигрыша в очках от
  реакции на грунт в опытах нет (+1,0 [−3,6; +5,4]).
- Что так будет в любом сценарии. Устойчиво повторяется реакция на сбой датчика: агенты с пережиданием заметили
  его за 2–9 с и переждали во всех 16 засчитанных прогонах Gazebo серии F1, где сбой пришёлся на время миссии. Реакция на
  смену грунта зависит от того, проедет ли робот по подорожавшему участку.

Если на показе пошло иначе: образцов собрано 6 из 7 или вопрос о грунте не возник — говорить по журналу, итог
всё равно «вернулся, ничего не задел». Если случился штраф — показать в журнале «Штраф: опасная зона…» и следом
гипотезу «около … опасная зона радиусом …, объезжать»: это тоже реакция на изменение среды.

## Бонусный трек: SLAM вместо готовой карты (60–90 секунд)

**В пять минут вживую не помещается:** режим запускается отдельной командой, стенд поднимается заново (40 с) и
объезд идёт 55–65 с. В пятиминутном показе на SLAM отводится 30–40 секунд после итога миссии: показать заранее
сделанный вывод `tools/slam_check.py` (или снимок страницы после объезда) и назвать числа из шага 4 таблицы ниже.
Вживую — на вопросах жюри или если основной показ закончился раньше.

Запуск отдельной командой — `pixi run demo --slam-map --open` (обычный показ перед этим остановить: `Ctrl+C`).
Роботу в этом режиме готовая карта не даётся совсем: стены, запас вокруг них и поправку позы он берёт у
SLAM Toolbox. В правом верхнем углу страницы подпись «карта SLAM, готовой нет», галочка «Известная геометрия» в «Слоях карты» снята.

| 4. Число | «Слои карты» → галочка «Известная геометрия»; числа — вывод `tools/slam_check.py` | «Начало координат карты совпадает с мировым со сдвигом в несколько сантиметров: в наших восьми прогонах 1,5–6 см и поворот до 1,3°. Все девять столбов найдены как кольца нужного радиуса не дальше 10 см от своих мест, с готовой картой совпало 96–99 % клеток» | серая подложка готовой карты совпала с чёрными стенами карты SLAM; проценты — в выводе `tools/slam_check.py` (на странице их нет) |
| 5. Миссия (если есть время) | «Запустить миссию» | «И автономная миссия идёт по той же карте SLAM» | как в основном показе, около 100 с |

Объезд занимает 55–70 с (10–12 м), цель — 15–20 с. Кнопку «Построить карту» нажимать через 10–15 секунд после
строки «Готов к заданию»: карте SLAM нужно несколько сканов. Точку в ещё не увиденном месте пульт отклонит строкой
«там, где SLAM ещё не видел пола» — это тоже можно показать до объезда.

Число для жюри и его повторение — в другом терминале при запущенном показе:

```bash
pixi run python tools/slam_check.py                       # сверка карты, какая есть сейчас
pixi run python tools/slam_check.py --explore --goal 1.5 1.2   # сам объедет, доедет до точки и сверит
```

Печатает: сколько пола увидено, долю клеток, совпавших с готовой картой, ошибку каждого из девяти столбов в
сантиметрах и сдвиг начала координат карты относительно мирового. Замеры 8.10 — в `research/findings/F2.md`.

Если SLAM Toolbox не запустился (на странице нет подписи про SLAM, кнопка «Построить карту» не появилась или
точки отклоняются строкой «Пригодной карты от SLAM Toolbox пока нет» либо «SLAM Toolbox ещё не прислал поправку
позы») — журнал `runs/_logs/demo-slam.log`;
запасной вариант — обычный показ `pixi run demo --slam`: робот едет по готовой карте, карта SLAM видна рядом.

Если робот в этом режиме встал, причина написана в строке сообщения, и он ждёт оператора — сам не поедет:

| Сообщение | Что это | Что делать |
|---|---|---|
| «SLAM Toolbox молчит: поправки позы нет уже N с» или «…карта не обновлялась N с» | узел SLAM завис или перегружен | подождать «SLAM Toolbox снова на связи» и нажать «Запустить маршрут» (объезд — «Построить карту») заново; не вернулся за полминуты — запасной вариант выше |
| «Точка N на новой карте SLAM оказалась в преграде…» | карта уточнилась, цель теперь в стене или столбе | поставить точку заново |
| «Новая карта от SLAM Toolbox непригодна для езды…» | SLAM прислал сетку, на которой негде встать | дождаться «Карта … снова пригодна» и нажать «Запустить маршрут» |
| «Езда остановлена: робот 10 с не продвигается…» | перед роботом преграда, которой нет на карте, или путь не проходим | поставить точку в другом месте или нажать «Запустить маршрут» |

В миссии при молчании SLAM или негодной карте агент сам прекращает езду по маршруту и продолжает, когда SLAM вернётся;
не вернулся за 20 с — едет на базу. Пока он ждёт, возможны короткие переползания на несколько сантиметров — это
штатная работа защиты, а не отказ.

## Бонусный трек: два робота, которые координируются (60 секунд)

Показываем запись в лаборатории, а не живой прогон: два робота в Gazebo — это две минуты и вторая загрузка стенда.
В пятиминутном показе запись идёт во второй вкладке, пока робот в основной миссии 36 секунд пережидает сбой
датчика (46–82-я секунда миссии): «Пуск», скорость 4× — прогон 113 с проходит за 30 секунд.

1. Запись из Gazebo (лежит в репозитории): `http://127.0.0.1:8765/#/run?file=M1gz/team/medium-3.json.gz` → «Пуск»,
   скорость 4×. Два TurtleBot3 (tb1 и tb2) со следами, пунктир — граница участков, справа лента «Переговоры роботов».
   Итог этой записи: 5 образцов из 5, оба вернулись, столкновений роботов 0, прогон 113 с.
2. Трудный сценарий из быстрого симулятора (готовится заранее, пара секунд):
   `pixi run python -m did.team_runner --level hard --seed 5 --mode team --exp M1demo`, затем
   `…#/run?file=M1demo/team/hard-5.json.gz`: 7 из 7, оба вернулись, прогон 85 с, 214 сообщений.

Что говорить. Общей памяти у роботов нет — только сообщения, и каждое видно в ленте: «эту цель беру я», «образец
собран, осталось три», «здесь опасная зона», «мой участок проверен, делим заново». На 80 сценариях против двух роботов
без связи, которые объезжают друг друга по лидару: прогон короче на 26 с (104 → 78), заряда уходит на четверть меньше
(100 → 74 единицы), оба вернулись в 80 прогонах из 80 против 75.

Чего не говорить. Что двое «набирают больше очков, чем один»: у команды двойной заряд и два бонуса за возврат, шкалы
разные. Что координация быстрее берёт последний образец: не берёт (+3,5 с, различие не показано). Что это измерено в
Gazebo: измерено в быстром симуляторе, в Gazebo — один прогон как проверка работоспособности.

## Что на странице

- **Карта.** Серое — эталонная карта арены (подложка, слой «Известная геометрия»), белое и чёрное — то, что робот
  увидел лидаром сам. Оранжевая линия — пройденный путь, синий пунктир — план. Карта закреплена: правая колонка
  прокручивается рядом с ней.
- **Шаги сверху** («Запуск — Карта — Задача — Движение — Результат») — где сейчас показ.
- **Задание.** «По заданному маршруту» — точки кликами и «Запустить маршрут»; «Собрать образцы и вернуться» — список
  «Агент» и «Запустить миссию». Под кнопками — строка состояния («Готов к заданию», «Робот следует заданному
  маршруту», «Возвращение на базу», «Идёт автономная миссия») и сообщения пульта об отказах.
- **Заряд, Пройдено, Счёт судьи** — то, что публикует судья (`/did/battery`, `/did/score`), и путь по одометрии.
  Ручная езда тратит заряд; перед миссией пульт просит судью начать прогон заново, поэтому миссия
  стартует с полным зарядом и со всеми образцами.
- **«Слои карты»** — «Лучи лидара», «Известная геометрия», «Оценки агента» (где агент ждёт образцы и что знает о
  грунте) и «Скрытые объекты для зрителя»: образцы, грунты и опасные зоны из состояния судьи. Последний слой по
  умолчанию выключен: агент этого не видит.
- **Последние решения агента** — пять последних строк журнала миссии, новая сверху: решения, гипотезы, проверки,
  странности и выводы расследований. Весь журнал, опыты и замеры — в записи: кнопка «Посмотреть этот прогон» в
  карточке «Результат миссии».
- **«Сравнить с LLM»** — сохранённые прогоны с настоящими ответами модели: два пути на одной карте.

## Если что-то пошло не так

| Что случилось | Что делать |
|---|---|
| Строка «Робот готовится к запуску» дольше минуты или справа вверху «Робот не подключён», окна Gazebo нет | `Ctrl+C`, ещё раз та же команда `pixi run demo …`. Журналы: `runs/_logs/demo-stand.log`, `runs/_logs/demo-pilot.log` |
| Робот едет рывками, задевает столбы | компьютер перегружен: закрыть лишние программы, остановить расчёты (`python3 tools/research.py pause`). Если не помогло — запасной вариант ниже |
| Робот упёрся или едет не туда | «Стоп», затем «На базу»; пульт сам отъезжает от преграды и строит путь заново |
| Миссия идёт плохо (столкновения, робот потерялся) | «Стоп» → «На базу» → «Сбросить прогон» → задание «Собрать образцы и вернуться» → «Запустить миссию» |
| Под кнопками сообщение, что судья не начал новый прогон | миссия не запущена: ещё раз «Запустить миссию» |
| Заряд кончился во время ручной езды | ничего: пульт сам попросит судью начать прогон заново |
| Gazebo завис или упал (робот замер и в окне, и на странице, секунды в плитке «Пройдено» стоят) | 8.10 так было один раз за три десятка запусков: сервер Gazebo перестал считать время. `Ctrl+C`, открыть запасную запись миссии (ниже) и рассказывать по ней; повторный запуск — 40 с |
| После `Ctrl+C` новый показ не поднимается | остались процессы прежнего: `pgrep -fl "gz sim"`, завершить их и запустить снова |
| Справа вверху «Робот не подключён» | проверить терминал с `pixi run demo`; страницу обновлять не нужно, она сама переподключится |

**Запасной вариант без Gazebo.** В терминале: `pixi run demo --fast --level hard --seed 2 --agent scientist_v2 --open`.
Это тот же класс пульта, та же арена, тот же судья и та же страница, только вместо Gazebo — быстрый симулятор внутри
сервера (справа вверху «Быстрый симулятор · №2»); одометрия в нём тоже уходит, и лидар её так же поправляет.
Сценарий показа тот же, шаги 1–6, время идёт как обычно, миссия — около 140 с. Проверено 9.10: 7 из 7, возврат,
счёт 91,8. Если стенд не подключён вовсе, быстрый симулятор включается и со страницы: карточка «Карта» → «С
изменениями», номер 2, «Применить».

**Запасная запись миссии из Gazebo** (лежит в репозитории, открывается при любом работающем сервере интерфейса):
`http://127.0.0.1:8765/#/run?file=F1demo/scientist_v2-hard-2-main-final.json.gz` → «Пуск», скорость 2× или 4×.
Это репетиция 9.10 на слитом коде: трудный уровень, сценарий 2, 7 из 7, возврат, счёт 91,8, 139 с. В ней есть обе
реакции: вопрос о расходе через полторы секунды после смены грунтов (вывод «грунт здесь изменился и стал дороже»)
и сбой датчика — замечен через 4 с, ожидание 36 с; кнопка «Показать расследования» открывает вопросы и опыты
агента. Рядом три записи репетиций 8.10 (`…-h2-r1`, `…-h2-r2`, `…-h2-gui` — с окном Gazebo; в `r2` и `gui` тревоги
о грунте на 31-й секунде нет) и запасная пара (`scientist_v2-hard-3-h3-r1`).

**Совсем запасной вариант** — видеозаписи в папке `demo/`: `pilot_fastsim.mp4` — полный сценарий на странице
пульта (быстрый симулятор), `pilot_gazebo_tour.mp4` и `gazebo_tour.mp4` — объезд в Gazebo: страница пульта и окно
Gazebo. Ключевые кадры — в `demo/shots/`.

**Репетиция без человека.** При запущенном показе команда
`pixi run python tools/demo_check.py --agent scientist_v2 --tour short --no-goal --expect hard 2 --min-samples 7 --clean` сама проходит
сценарий показа (объезд по четырём точкам, миссия) и печатает, что получилось на каждом шаге: счёт, собрано, возврат,
штрафы, наибольший простой, реакцию на три изменения среды и долю опоздавших тактов (больше 3 % — компьютер был
перегружен, репетиция не засчитывается). «Репетиция прошла» значит: объезд пройден по всем точкам, миссия шла на
новом прогоне судьи (сброс подтверждён), робот вернулся без столкновений, запись прогона найдена; `--min-samples 7`
требует все семь образцов сценария 2, `--clean` — ни одного заезда в опасную зону и ни одного ложного сбора
(есть ещё `--min-score X`). Без ключей — прежний полный сценарий: шесть точек, цель, домой, миссия.
Ключ `--save runs/F1demo` сохраняет запись миссии. Разбор любой записи по секундам:
`pixi run python tools/demo_pick.py --story runs/F1demo/scientist_v2-hard-2-h2-r1.json.gz`.

## Команды

```bash
pixi run demo --level hard --seed 2 --agent scientist_v2 --open   # показ: трудный уровень, сценарий 2 (агент выбирается на странице)
pixi run demo --level hard --seed 3    # запасная пара: тот же агент, сценарий 3
pixi run demo                          # Gazebo с окном, средний уровень, сценарий 3 (без изменений среды)
pixi run demo --fast                   # без Gazebo, быстрый симулятор
pixi run demo --no-gui                 # Gazebo без окна (проверка на слабой машине)
pixi run demo --slam                   # обычный показ, рядом — карта SLAM Toolbox (переключатель под картой)
pixi run demo --slam-map               # бонусный трек: без готовой карты, робот едет по карте SLAM Toolbox
pixi run demo --slam-map --slam-start settle   # то же, но SLAM Toolbox стартует после оседания робота (опыт F1: не помогло)
pixi run python tools/slam_check.py    # сверка карты SLAM с готовой картой и со столбами мира
pixi run python tools/demo_check.py --agent scientist_v2 --tour short --no-goal --expect hard 2 --min-samples 7 --clean   # репетиция показа
pixi run python -m did.team_runner --level hard --seed 5 --mode team --exp M1demo   # запись прогона двух роботов
pixi run python tools/gz_record.py --out demo/gazebo.mp4 --view iso   # записать окно Gazebo
```
